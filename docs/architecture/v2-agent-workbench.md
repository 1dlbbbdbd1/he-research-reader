# H’s Agent Workbench v2：当前实现契约

> 状态：本地开发中，尚未发布。本文记录已经进入源码和测试的边界，以及仍需真实桌面验收的部分，不把路线图写成完成事实。

## 产品入口

主导航固定为“工作台 / 运行 / 项目 / 科研资产中心 / 设置”。工作台负责目标与最近 Run，运行页集中显示授权、计划轨道、等待决定、验收和成果，项目页管理可选能力。“科研资产中心”只收拢旧入口，不迁移、不删除旧研究数据，原有阅读、文献、实验、任务、证据、图谱、复盘和写作视图继续复用原接口。

## Runtime

Run 状态为：

`draft → awaiting_authorization → running → replanning / waiting_human / paused / verifying → completed / failed / cancelled`

当前循环具备以下硬规则：

1. 创建 Run 后只生成计划，不执行；必须先审核任务级权限。
2. Planner 只能从主进程公布的工具名中生成结构化步骤；未知工具、超长输入和 shell 字符串式命令不会进入计划。
3. 普通任务的工具首次失败后可由 Planner 形成下一版计划；拥有固定能力合同的科研流程失败时不会交给 Planner 改写阶段，而是保留失败证据并进入 `waiting_human`。
4. 每次步骤前后和验收后都写检查点。应用重启会暂停未完成 Run，并使旧任务授权失效。
5. 一次连续循环最多 50 步；超过上限自动等待人工决定。
6. Verifier 只接收目标、验收条件、步骤标题/状态、成果类型/标签/哈希，不接收文件正文、命令输出、本机路径或截图。通过项必须引用数据库中真实存在的步骤或成果 ID。

### 能力合同与运行前检查（2026-08-14 增量）

- 能力注册表与工程合同分离：既有十项注册不被整表替换；十项能力均在 `capability-contracts.cjs` 声明版本、输入/输出 schema、必需/可选工具、连接器、允许工具、固定阶段、人工确认点、QA、示例和夹具。
- `listCapabilityPacks()` 会用工具注册表的真实可用性生成 preflight；没有合同或缺少任一必需工具时状态为“缺少工具”，不会进入新建目标下拉框。
- 能力输入先按 schema 校验，再作为 `run_created` 只追加事件的一部分持久化；界面传来的 JSON 字符串按 `object` 字段解析，数字字段正规化，合同默认值由主进程应用。固定工作流输入只允许引用 `$input`、已完成上游步骤或最新结果版本。
- 任务授权会再次检查能力所需域名、应用和输入/输出路径。引用核验要求 `api.crossref.org`，外发前还会显示参考文献条目数量和数据类型并二次确认。
- 结构化结果继续复用 schema v19：每个结果版本新增一条 `agent_artifacts(kind=report)`，通过稳定 `resultId`、递增 `version`、`reviewState` 和来源元数据串联；旧版本不更新、不删除。这样无需为首批能力提前迁移用户研究库。
- 通用 Planner 仍服务普通任务；拥有固定合同的能力不再让 Planner 临时创造阶段或越过 `allowedTools`。

## 权限与工具

任务授权分别保存可读目录、可写目录、域名、程序、参数前缀、应用、是否允许发送文件内容、是否允许截图。文件路径在 Main 进程解析真实父目录，防止 `..`、符号链接或 Windows 目录联接越界。命令使用 `spawn(executable, args, { shell: false })`，不执行模型拼接的命令字符串。

当前工具：

- 文件：项目观察、2 MB 内文本读取、临时文件加原子重命名的版本化写入和 SHA-256。
- 网络：受域名限制的 HTTP 读取。
- 浏览器：Playwright Core 启动独立 Workbench profile，只选择系统已安装的 Edge 或 Chrome；打开、读取、点击、填写、下载和关闭都经 Main 进程。下载目标必须是授权写入路径且不能覆盖已有文件。
- Office：通用副本工具继续只读另存；Word 规范排版使用独立固定脚本。检查、排版和 QA 每一步都先创建与输入 SHA-256 一致的临时字节副本，Word 不接收用户原路径；排版生成新 `.docx`，QA 真实重新分页并生成版本化异常报告。
- 系统综述：协议、资料库/JSON 导入、DOI/规范化题名/作者年份联合去重、标题摘要与全文筛选、证据矩阵、偏倚字段、PRISMA 统计和结论追溯检查均为本地确定性工具。排除没有理由、筛选未完成或综合结论没有映射到纳入文献稳定 ID 时禁止完成态导出。
- 证据化精读/翻译：固定 Run 直接读取当前结构化阅读版本，复用逐段缓存和术语表；翻译失败按段保留，DOI/公式/引用标记受保护。学术翻译额外调用 Word 生成 DOCX，以 `ExportAsFixedFormat` 真实渲染 PDF，并记录重新分页后的页数、哈希和异常。
- 审稿回复/专利：ReviewComment、处理状态、拟修改位置和真实资料链接形成证据矩阵；无修改稿位置不得声称“已经修改”。专利事实必须来自报告标题章节或报告中可找到的原文摘录，权利要求逐项映射事实；新颖性和法律判断没有真实来源时固定为 `not_performed`。
- 路线图/科研绘图：路线图先产出 JSON，人工编辑版本由后续步骤重新解析，再检查孤立节点、环路、方向和溢出并导出 Draw.io/SVG。科研图表先锁定原始数据哈希与清洗合同，另存清洗数据；人工编辑规格后由 Electron 真渲染 SVG/PNG/JPG，并检查尺寸、DPI、文字、图例、色盲调色板和面板编号。
- 因果推断：DID、RDD、IV、PSM、SCM 使用独立字段合同和对应诊断；主进程只在用户授权的 `python.exe` 中调用固定 Python + NumPy 脚本，保存实际代码、Python/NumPy 版本、可执行路径、数据哈希、参数和 JSON 结果。诊断不过时报告只保留统计估计，不允许标成可靠因果结论。
- VS Code：官方 `code --reuse-window --goto`，代码写入和测试仍经过文件/命令边界。
- 视觉：Electron `desktopCapturer` 只列出和截取用户授权窗口；最多 20 个指定敏感区域会在 Main 进程内存中遮蔽，截图默认不持久化。通用键鼠只接受点击、文本和固定按键白名单，执行前二次确认，并校验前台窗口句柄、标题、坐标与前后画面；窗口变化立即失败。

删除或移动原件、发布、Git push/PR/Release、外部提交、上传、安装、提权、付款、正式科研结论和跨应用动作始终要求二次确认。高风险批准由 Main 进程记录为决定证据，只消费一次，不信任模型在输入中自称“已批准”。
